# 七つの太陽 — 設計分解

火起こし × デッキ構築ローグライクのプロトタイプ。世界のすべての火が消えたあと、燃料を正しい順序でくべて温度を上げ、七つの太陽を昇らせながら世界を焼き尽くす。

この文書には二つの目的がある。**遊んだことのない人にこのゲームの面白みが伝わること**と、**ゼロから再実装できること**。前半が体験の記述、後半が完全仕様。最後に「この設計のどこが他のゲームに持ち出せるか」を分離して書いた。

---

## 0. 30秒でわかる

- **炉に燃料を下から5枚積む**。火は下から上へ伝わる
- 各燃料には**着火点**があり、その時点の温度が足りないと**そこで伝播が止まり、上に積んだものが全部無駄になる**
- 温度は加算だけでなく**触媒・共鳴・連鎖・乗算**で伸びる。伸ばし方は積む順序で決まる
- 敗北条件は HP ゼロではなく、**温度が着火点を下回った瞬間**
- 章のボスは「燃やせない物」。枯野 → 大河 → 湖 → 大海 → 世界を支える三層 → 須弥山 → 火そのもの
- 一章クリアごとに**空の太陽が一つ増え**、以後すべての温度に乗り続ける
- 到達温度は第一章の 10⁵ から最終章の 10¹⁸⁰ まで伸びる

一言でいえば、**「並べる順番だけで数字が10桁単位で変わるゲーム」**である。

## 1. 追体験 — 第一夜、最初の5枚

ここは実際のエンジン出力をそのまま使う。数値はすべて実測値で、脚色はない。

### 手札が配られる

種火が一つ。温度 **1°（燻り）**。画面は暗く、下から立つ焔はほとんど赤褐色にくすんでいる。手札は7枚：

```
麻屑        要 燻り   発熱+3     [屑]     以降の必要段 −1
杉の葉      要 燻り   発熱+4     [屑/木]  40%で火の粉
乾いた薪    要 赤熱   発熱+14    [木]
松脂        要 燻り   次×3       [樹脂]   触媒同士は掛け算で合成
松ぼっくり  要 燻り   発熱+5     [木]     55%で爆ぜた種。種はさらに連鎖する
送風        要 燻り   —          [行動]   同時燃焼本数だけ累計を乗算
小麦粉      要 赤熱   —          [粉]     単体では無意味。粉2枚で粉塵爆発
```

この7枚から5枚選び、**下から積む順を決める**。

最初に目に入るのは「要 赤熱」の乾いた薪だ。発熱+14 はこの手札で最大だが、現在は燻り。**下に何かを積んで赤熱まで持ち上げないと、こいつは着火しない**。着火点は制約であると同時に、「そこまで温度を上げろ」という指示でもある。

### まず素直に積んでみる（着火点の昇順）

安全策は着火点の低い順だ。麻屑 → 杉の葉 → 松ぼっくり → 送風 → 乾いた薪。これなら全段が確実に燃える。

```
● 麻屑      +3                            →      4°（燻り）
● 杉の葉    +10   共鳴×2.5（2連[屑]）     →     14°（赤熱）
   ⤴ 相転移 ×1 — 炉は用済みになった（以降の乗算 +0.75）
   連鎖 1世代 / 1回発火（酸素残13）        →     30°（赤熱）
● 松ぼっくり +31  共鳴×6.25（3連[木]）    →     61°（赤熱）
   共鳴3連 ×3.25                          →    198°（橙炎）
   ⤴ 相転移 ×1（以降の乗算 +1.5）
   ⚠ 臨界 m=1.70 ≥ 1 — 酸素が尽きるまで止まらない
   連鎖 5世代 / 9回発火（酸素残4）         → 100,804°（蒼閃）
   ⤴ 相転移 ×3（以降の乗算 +3.75）
● 送風      +0                            → 100,804°（蒼閃）
   送風 ×7.75                              → 781,234°（蒼閃）
● 乾いた薪  +14                           → 781,248°（蒼閃）
```

**10万倍。** 麻屑と杉の葉が同じ「屑」タグで共鳴し、杉の葉と松ぼっくりが「木」で3連になる。松ぼっくりのところで警告が出た——**臨界**。連鎖が自分を再生産する速度が1を超え、酸素が尽きるまで止まらなくなる。5世代で9回発火し、温度は198°から10万°へ跳ねた。

画面の色が、赤 → 橙 → 白 → 青 → 蒼と一気に駆け上がる。**数字を読む前に、色で「何かとんでもないことが起きた」と分かる。**

そして最後の乾いた薪が `+14`。10万°の炉に薪を1本足しても、**もう何も起きない**。

### ここに気づくのが、このゲームの入り口

最後の2枚がひどい。

- **送風**は「同時燃焼本数だけ累計を乗算」する。4本目に置いたので ×4（相転移ボーナス込みで ×7.75）。**5本目に置けば ×5 だった**
- **乾いた薪 +14** は最上段に置くと完全な無駄。**下の方に置いて、その加算が後続の全乗算に乗るようにすべきだった**

つまり **加算は下、乗算は上**。着火点の昇順は、この原則と真っ向から衝突する。送風の着火点は全カード中もっとも低い「要 燻り」なので、昇順で積むと下の方に来てしまうのだ。

### 積み直す

麻屑 → 杉の葉 → **乾いた薪** → 松ぼっくり → 送風。薪を3番目に繰り上げ、送風を最上段へ。

```
● 麻屑      +3                            →         4°（燻り）
● 杉の葉    +10   共鳴×2.5（2連[屑]）     →        14°（赤熱）
   ⤴ 相転移 ×1（以降の乗算 +0.75）
   連鎖 1世代 / 1回発火                    →        30°（赤熱）
● 乾いた薪  +88   共鳴×6.25（3連[木]）    →       117°（橙炎）
   ⤴ 相転移 ×1（以降の乗算 +1.5）
   共鳴3連 ×4.00                          →       469°（橙炎）
● 松ぼっくり +78  共鳴×15.625（4連[木]）  →       547°（橙炎）
   共鳴4連 ×7.75                          →     4,240°（白熱）
   ⤴ 相転移 ×1（以降の乗算 +2.25）
   ⚠ 臨界 m=1.90 ≥ 1
   連鎖 4世代 / 10回発火（酸素残3）        → 9,528,823°（虚炎）
   ⤴ 相転移 ×3（以降の乗算 +4.5）
● 送風      ×9.50                          → 9.05×10⁷°（劫火）
```

**9,050万°。** さっきの 78万° の 116倍。同じ5枚、違うのは並べただけ。

何が変わったか：

1. 薪を3番目に入れたことで「木」タグが**4連**になり、共鳴が ×6.25 から ×15.625 へ
2. 薪の +14 が触媒と共鳴を通って **+88** に化けた
3. その +88 が、上の連鎖と送風の乗算**全部に**乗った
4. 送風が5本目になり ×9.50

そして最後の一撃で色が**劫火**に変わる。ページ全体の輝きが赤紫に染まる。

これが、このゲームの1ラウンドの全部だ。**5枚を並べ替えるだけで、100倍が動く。**

### そして「実は選び方が間違っていた」

ソルバに手札7枚から全3,619通りを探索させると、答えはこうなる：

```
着火点の昇順           10^2.26
同じ5枚での並べ替え最適 10^6.81   ← 並べ替えだけで +4.5桁
手札7枚からの完全最適   10^8.28   ← 選び直しでさらに +1.5桁
```

**松脂（触媒）を切って松ぼっくり（連鎖）をもう1枚入れる**のが正解だった。触媒 ×3 より、連鎖の期待値の方が大きい。

順序を考えるゲームだと思って遊んでいると、**そもそも何を選ぶかで1.5桁を落としている**。この二段構えが、1ラウンドあたりの意思決定の厚みになっている。

### 夜は続く

ラウンドが終わると **メトラ**（ヘラクレイトス「定めの分だけ燃え、定めの分だけ消える」）で温度が落ちる。手札が引き直され、また5枚を選ぶ。2ラウンドで一つの章。

章末、目の前の**枯野**に必要な発火点は 10⁵。届いていれば枯野が燃え、**空に一つ目の太陽が昇る**。太陽は以後すべての温度に ×10 で乗り続け、同時に**世界を乾かして全燃料の着火点を下げる**。後半ほど何もかもが燃えやすくなる。

そして燃やした枯野は**灰**になってデッキに入る。海を燃やせば「水」が、須弥山を燃やせば「太陽」が手札に来る。**倒した敵がそのまま次の燃料になる。**

第七章で燃やす対象は**火そのもの**。最後に自分自身を燃料としてくべたとき、ランが終わる。

## 2. 面白さの正体 — 7つの発明

ここからは「なぜ面白いのか」を仕組みに分解する。各項目の末尾に**移植可能性**を書いた。他ゲームと混ぜるときはここを見ればいい。

### 2.1 火は所有できない ⇒ ローグライクが物語の側から正当化される

火は持ち越せない。毎回ゼロから起こすしかない。だから**メタ進行に炎そのものを繰り越してはいけない**。引き継ぐのは技法だけ（「弓錐式を覚えた」「松脂の性質を知った」）。

多くのローグライクは「なぜ毎回最初からなのか」に答えを持たず、ゲーム的都合として黙認されている。このテーマはその問いに**題材の側から**答えを持っている。

> **移植可能性**：高いが、テーマ依存。「毎回リセットされることが題材の本質である」という素材を選べるかどうか。火、夢、潮汐、演奏、料理、天気。

### 2.2 上限を罰ではなく報酬にする — 相転移

初期案では「炉の耐熱温度」を上限にしたが**却下**した。伸ばすほど怖くなる構造はインフレゲームの爽快感を殺す。

代わりに**相転移**を置いた。閾値を超えると炉は壊れるのではなく**用済みになる**。

- 石の炉が溶ける → 溶けた炉自体が燃料になる
- その火が大気を焼き切る → 火は容器を必要としなくなる
- 最終的に火は場所を持たず、概念として燃えている

実装上は「**解決中に段が1つ上がるたび、以降のすべての乗算に +0.75**」。ペナルティはゼロ、純粋な恒久ブースト。

これが数値的にも最重要だった。**熱 → 燃焼速度↑ → 熱↑** という物理の正のフィードバックが、そのまま数式になる。上の追体験ログで乗算が ×0.75 → ×1.5 → ×2.25 → ×4.5 と膨らんでいくのがそれ。

> **移植可能性**：**非常に高い。テーマ非依存。** 「閾値通過を罰ではなく恒久ブーストにする」だけで、どんな数値ゲームにも入る。閾値が近づくと緊張し、超えると加速する。しかも指数関数が自然に出てくるので、インフレを別途設計しなくていい。

### 2.3 着火点は「順序の縛り」ではなく「枠の値段」

ここが設計上いちばん重要な発見なので、結論から書く。

> **定理**：ある並びで全段着火できるなら、**着火点の昇順でも必ず全段着火できる**。

証明は交換論法。隣接する2枚 a（着火点低）b（着火点高）について、順序 a→b の要求は「T ≥ ign(a)」かつ「T + heat(a) ≥ ign(b)」。順序 b→a の要求は「T ≥ ign(b)」かつ「T + heat(b) ≥ ign(a)」。ign(a) < ign(b) なので前者の方が常に緩い。温度は単調増加なので、これが全体に伝播する。

**つまり着火点は順序を縛っていない。** 「途中に着火点の高いものを挟むと上が全部死ぬ」という負け方は確かに存在するが、それは単に下手な並べ方があるというだけで、うまい並べ方は一意に決まる。パズルになっていない。

では着火点は何をしているのか。**手札の枠を縛っている。**

> マグネシウム（発熱+70、この手札の主砲）を着火させるには累計40が必要。ところが手持ちの着火役を全部使っても15にしか届かない。**主砲を撃つには、火力ゼロの踏み台に枠を何枚も食われる。**

「主砲を諦めて共鳴を組む」か「踏み台に3枠払って主砲を通す」か。これが本当の意思決定だ。そして**麻屑（全燃料の着火点を下げる）は、その踏み台の枚数を減らすカード**である。役割は「順序の解除」ではなく「**枠の節約**」。

この読み替えをすると、「跳ね上がるものほど着火点が高い」というルールが効いてくる。**着火点 = そのカードを撃つために手札枠を何枚犠牲にするかの値段**になるからだ。

> **移植可能性**：**高い。テーマ非依存。** 単調増加する資源に対して「必要値」でカードを縛る設計は広く使えるが、**そのままでは順序パズルにならない**ことを知っておく必要がある。必要値はコスト（枠・選択）に効かせ、順序の面白さは別のところから持ってくること。

### 2.4 乗算は常に最後が正解 ⇒ 非自明性は「位置に非単調な効果」からしか生まれない

同じく重要な負の発見。累計に乗る乗算カードは：

- 後ろに置くほど乗算対象が大きい → **払いが必ず増える**
- 後ろに置くほど温度が高い → **着火も必ず楽になる**
- 加算は可換なので、乗算を後ろにずらしても他カードの着火判定は悪化しない

**デメリットが一つも存在しない。** 「乗算は最後」はプレイヤーが考えて到達する解ではなく、例外なく正しい機械的手続きである。

したがって、並べ替えを面白くできるのは次の3種類だけになる。

| 種類 | 例 | 置きたい位置 |
|---|---|---|
| **前方参照** | 松脂（次の1枚を ×3） | 最大の加算の直前。最後に置くと無駄 |
| **隣接連続** | タグ共鳴（同タグ3連続） | タグ順は着火点順と無関係 → **真の衝突** |
| **後方伝播** | 確率連鎖 | 後ろに残り札が多いほど伸びる → 前に置きたい |

そして**送風**が全部を体現している。着火点は全カード中最低の「要 燻り」なのに、最適位置は上から2番目。**着火点の昇順で積むと最下段に来て、燃焼1本 ×1 の無意味なカードになる。**

実測すると、最適解における各カードの平均位置（0.0 = 最下段、1.0 = 最上段）はこうなった：

```
炭          0.20 ▂  加算            麻屑        0.21 ▂  着火役
松脂        0.27 ▃  触媒            コークス     0.29 ▃  大加算
乾いた薪    0.33 ▃  加算            小麦粉      0.37 ▃  粉（居るだけでいい）
杉の葉      0.40 ▄  連鎖            テルミット   0.40 ▄  大加算
松ぼっくり  0.55 ▅  連鎖            重油        0.61 ▅  累計乗算
マグネシウム 0.69 ▆  乗算+大加算     雷          0.72 ▆  乗算+大加算
水          0.76 ▇  乗算+大加算     送風        0.76 ▇  累計乗算
生木        0.78 ▇  乗算+大加算     炎そのもの   0.84 ▇  二乗
```

**下から「加算 → 連鎖 → 乗算 → 二乗」の4層**。これが唯一の指針で、あとは着火点との折り合いをどうつけるかの話になる。

> **移植可能性**：**最重要の教訓。テーマ非依存。** 「加算 → 乗算」の順序ゲームを作るなら、**乗算を後ろに置くコストを人工的に作らないと自明に解ける**。前方参照・隣接連続・後方伝播のどれかを必ず併置すること。Balatro のジョーカー順序が面白いのも、単なる ×mult ではなく相互参照があるから。

### 2.5 連鎖は分岐過程 — 臨界 m = 1 を演出装置にする

「木を燃やしたら確率で木の実が爆弾になり、その個数も確率で変動する」。数学的にはこれは**分岐過程（branching process）**そのもので、1回の発火が平均 m 個の次の発火を生むとき：

- **m < 1** → 連鎖総数の期待値は **1/(1−m)** に収束（m=0.5 で平均2回、m=0.9 で平均10回）
- **m ≥ 1** → **発散する**

m は 0.9 と 1.1 の間で挙動が**質的に変わる**。ここをそのままゲームにした。

> 通常のカードは m < 1。**タグ共鳴が連鎖確率を押し上げる**（同タグ n 連続で +0.15×(n−1)）。合計で m が 1 を超えた瞬間が**臨界**で、酸素が尽きるまで止まらない。

追体験ログの `⚠ 臨界 m=1.90 ≥ 1` がそれ。理論上は無限に燃え続けるので、**上限を酸素にする**。酸素の残量が連鎖の世代数を打ち切る。

演出としても優れている。臨界を超えたときだけ連鎖が延々続くので、**ジャックポットが「回数」で示せる**。数字を読ませなくていい。

> **移植可能性**：**高い。テーマ非依存。** 「確率で追加発動する」系のメカニクスを入れるなら、分岐過程として設計し、m=1 を明示的な演出上の境界にすること。m を上げる手段を別系統（ここではタグ共鳴）に持たせると、「連鎖を伸ばすために役を組む」という副次的な目標が生える。上限資源（酸素）は必須。

### 2.6 対数スケール = 色 — インフレを読ませずに理解させる

得点が 10⁹ になっても、プレイヤーは数字ではなく**炎の色**で理解できる。黒体放射がそのまま UI になる。

| 段 | 名 | 温度 | ルール変化 |
|---|---|---|---|
| 0 | 燻り | 10⁰ | 水で即死 |
| 1 | 赤熱 | 10¹ | 鉄が溶ける |
| 2 | 橙炎 | 10² | 延焼開始 |
| 3 | 白熱 | 10³ | **水も燃料になる** |
| 4 | 青炎 | 10⁴ | 炉が意味を失う |

段が上がると**倍率だけでなくルールが反転する**のが肝。低温では水は即死級のリスクだが、白熱域では熱分解して最大級の燃料に変わる。**序盤のデバフカードが終盤の最強カードになる。**

実装上、GUI ではページ全体の輝きと画面下から立つ焔の色が段に連動する。**10^180 という数字を読まなくても、色で今どこにいるかが分かる。**

段の名前は仏教宇宙論から40段ぶん取った：燻り → 赤熱 → 橙炎 → 白熱 → 青炎 → 蒼閃 → 虚炎 → 劫火 → 白劫 → 焦熱 → 大焦熱 → 無間 → 壊劫 → 空劫 → 成劫 → 住劫 → 初禅 → 二禅 → 三禅 → 四禅 → 梵天 → 光音 → 遍浄 → 広果 → 無想 → 無煩 → 無熱 → 善現 → 善見 → 色究竟 → 空無辺 → 識無辺 → 無所有 → 非想 → 不可説 → 不可説転 → 阿僧祇 → 那由他 → 恒河沙 → 無量大数。

> **移植可能性**：**非常に高い。テーマ非依存。** インフレゲームでは、スコアそのものより「今どの段にいるか」を色・名前・音で示す方が理解が速い。段ごとにルールを反転させると、同じカードの意味が周回で変わる。

### 2.7 報酬 = 倒した敵そのもの

**くべる**（順序と触媒で温度を作る）→ **燃やす**（対象の発火点を超える）→ **灰を拾う**（燃やした対象が新しい燃料としてデッキに入る）→ 繰り返し。

鉄の門を燃やせば「鉄」が、海を燃やせば「水」が手札に加わる。**デッキ構築の報酬が倒した敵そのもの**なので、「なぜこれが手に入るのか」で悩まなくて済む。カード名を考える手間も、獲得タイミングの説明も、全部これで片付く。

そしてノルマが**数字ではなく物**になっているのが効いている。「なぜ 10⁹ 度が必要なのか？」→「海を燃やすから」。数字が大きくなるのではなく、**燃やす対象がおかしくなっていく**。プレイヤーが見るのはスコアではなく、目の前の物が燃えるかどうかだ。

> **移植可能性**：**高い。** 「障害を克服したらその障害自体が道具になる」は広く使える。カード獲得の理由づけが自動化される。元ネタはカグツチ（生まれた瞬間に母を焼き殺し、その死体の断片から山の神々が生まれる）。

## 3. 完全仕様（再実装用）

ここから下は実装のための記述。この節だけで再実装できる。

### 3.1 数値表現

**温度は 10^L として指数 L だけを持つ。** 最終章で 10^180 に達し、二乗系カードで簡単に 10^1000 を超えるため、float64（上限 10^308）では破綻する。

```
ladd(L, h)  ≔ log10(10^L + h)      加算
  h ≤ 0             → L
  L − log10(h) > 18 → L            （h が無視できる）
  log10(h) − L > 18 → log10(h)
  otherwise         → max(L,lh) + log10(1 + 10^(−|L−lh|))

lmul(L, m)  ≔ L + log10(m)          乗算
二乗        ≔ L × 2
e 乗        ≔ L × e
段          ≔ floor(L)
```

表示は L < 7 なら実数、以上なら `仮数 × 10^指数`。

### 3.2 カードのデータ構造

```
Card {
  name      : 名前
  ign       : 着火点（必要な段。0 = 燻り、1 = 赤熱、…）
  heat      : 発熱（加算値）
  mult      : 累計への乗算（デフォルト 1.0）
  catalyst  : 次の1枚の発熱への倍率（デフォルト 1.0）
  tags      : タグ集合（屑/木/樹脂/炭/湿/油/粉/金属/行動/灰/概念/火）
  chain_p   : 連鎖発火の確率
  chain_n   : 生成数の範囲 [min, max]
  spawn     : 生成物のカード名
  special   : 特殊効果ID

### 3.3 解決パイプライン

**1枚ごとのループ**である点が重要。「全部投入 → 一括判定」ではなく、1枚解決するごとに温度が変わり、それが次の着火判定に影響する。

```
resolve(stack, L, oxygen, suns):
  relief_global = suns // 2          # 太陽が増えるほど世界が乾く
  relief_extra  = 0                  # 麻屑による軽減の累積
  ignore_ign    = false              # 「燃えない何か」
  oil_left      = 0                  # 重油の残り効果枚数
  catalyst      = 1.0                # 持ち越し触媒
  streak        = 1                  # 同タグ連続数
  prev_tags     = {}
  heats         = []                 # 灰の平均計算用
  burned        = 0                  # 同時燃焼本数（送風用）
  phase         = 0                  # 相転移の累積回数
  mp_log        = 0                  # 適用した倍率の総積（log10）

  n_dust  = stack 中の「粉」タグ枚数
  n_metal = stack 中の「金属」タグ枚数

  for c in stack:                    # 下から順に

    # ---- 1 着火判定 ----
    need = max(0, c.ign − relief_global − relief_extra − (oil_left>0 ? 2 : 0))
    if oil_left > 0: oil_left −= 1
    if not ignore_ign and need > floor(L):
        「c は着火せず。上の全カードは不発」
        if 「湿」in c.tags: L −= 1        # 湿ったものが火を奪う
        break

    # ---- 2 発熱の確定 ----
    base = c.heat
    if c.special == ash:      base = mean(heats)   # これまでの発熱の平均
    if c.special == thermite and n_metal ≥ 3: base = c.heat × 10

    common = c.tags ∩ prev_tags
    streak = common ? streak + 1 : 1
    res    = RESONANCE_BASE ^ (streak − 1)
    heat   = base × catalyst × res

    # ---- 3 加算 ----
    L = ladd(L, heat);  burned += 1;  heats.append(base)
    bump(L)                                        # 相転移判定

    # 触媒の持ち越し。触媒同士が隣接したら掛け算で合成される
    catalyst = (c.catalyst ≠ 1 and catalyst ≠ 1) ? catalyst × c.catalyst : c.catalyst
    prev_tags = c.tags

    # ---- 4 累計への乗算 ----
    if streak ≥ 3: L = mul(L, RESONANCE_BASE ^ (streak − 2))   # 共鳴は累計にも乗る
    L = mul(L, c.special == bellows ? burned : c.mult)

    # ---- 特殊 ----
    tinder     : relief_extra += 1
    oil        : oil_left = 2
    oxygen     : oxygen += 12
    unburnable : ignore_ign = true
    square     : L = L × 2                          # 温度を二乗
    time       : L += mp_log ; mp_log ×= 2          # 倍率の総積を再適用
    sun        : L = L × (1 + 0.35 × max(1, suns))  # 温度を累乗
    copy       : 直前の1枚をもう一度 resolve（深さ上限3）

    # ---- 5 連鎖 ----
    if c.chain_p > 0 and oxygen > 0:
        bonus = 0.15 × (streak − 1)                 # 共鳴が連鎖確率を押し上げる
        m     = min(0.95, c.chain_p + bonus) × mean(c.chain_n)
        if m ≥ 1: 「臨界」を表示
        L, oxygen = run_chain(c, L, oxygen, bonus, phase)

  # ---- 6 全体再点火 ----
  if n_dust ≥ 2 and burned ≥ 1:
      L += log10(DUST_MULT) × (n_dust − 1) + max(0, mp_log)   # 粉塵爆発
  if suns ≥ 1:
      L += suns                                               # 太陽 ×10^suns

  return L, oxygen
```

補助関数：

```
bump(L_before, L_after):                # 相転移
  d = floor(L_after) − floor(L_before)
  if d > 0: phase += d                  # 以降の全乗算に PHASE_BONUS × phase が加算される

mul(L, m):                              # 相転移ボーナス込みの乗算
  m_eff = m + PHASE_BONUS × phase
  mp_log += log10(m_eff)
  return L + log10(m_eff)

run_chain(src, L, oxygen, bonus, phase):    # 分岐過程
  queue = [src]; gens = 0
  while queue and oxygen > 0 and gens < CHAIN_CAP_GEN:
      gens += 1; next = []
      for s in queue:
          if not s.spawn: continue
          if random() ≥ min(0.95, s.chain_p + bonus): continue
          for k in 1..randint(s.chain_n):
              if oxygen ≤ 0: break
              oxygen −= 1
              ch = CARD[s.spawn]
              L = lmul(ladd(L, ch.heat), ch.mult + PHASE_BONUS × phase × 0.25)
              next.append(ch)
      queue = next
  return L, oxygen
```

**注意点**：`mul` は必ず `bump` を伴う。乗算で段をまたぐと、その場で以降の乗算が強くなる。この自己参照が指数的成長の源。

### 順序パズルは機能しているか

260ハンドで「着火点の昇順が最適解と一致する割合」を計測：

```
昇順ソートが最適だった割合  : 34.0%
昇順ソートの平均達成率      : 59.6%（最適比、指数で計算）

## 5. 設計中に踏んだ罠

同じ轍を踏まないための記録。**どれも「作ってから測って初めて分かった」もの**で、机上では見えなかった。

### 5.1 昇順ソート定理（→ 2.3）

「着火点で順序を縛る」というアイデアは、**そのままでは順序パズルにならない**。実装して総当たりを回すまで気づかなかった。順序ゲームを設計したら、**まず総当たりして「自明な機械的手続きで解けないか」を確認する**こと。

### 5.2 単位の不整合

初期の設計メモでは着火点が摂氏の実在値（薪 = 180℃）、発熱がゲーム的な小さい値（+10）で書かれていた。麻屑を燃やしても温度1にしかならないので、**180℃に永遠に届かない**。

解決：**着火点を「色の段」（対数スケール）で判定する**。これで温度スケールと着火点スケールが分離され、同時に「段が上がるとルールが反転する」という別の設計と直結した。

### 5.3 加算しか触らない効果は、高段で無意味になる

最初の実装では「跳ね上がらない」問題が出た。原因は、ほとんどの効果が**1枚の発熱（加算）にしか触れていなかった**こと。青炎域で `+70` は誤差でしかない。

桁を跳ねさせるには、**乗算の回数を増やす／乗算が乗算を強化する**構造が要る。追加した7つ：

1. 相転移（段を跨ぐたびに以降の全乗算が強化）
2. 触媒の連鎖合成（×3, ×3 → ×9）
3. 共鳴の格上げ（発熱だけでなく累計にも乗算）
4. 連鎖の子が加算ではなく乗算を持つ
5. 二乗（炎そのもの）と累乗（太陽）
6. 粉塵爆発が「倍率の総積」を再適用
7. 太陽が ×10^n

結果、第1章の初期デッキだけで 1° → 10^7 まで伸びるようになった。

### 5.4 float64 は 10^308 で壊れる

「バカみたいな数値」を目指すなら必ず当たる。**内部表現を温度そのものではなく指数（log10）にする**のが唯一の解。加算だけ `log10(10^a + b)` の安全な実装が必要になるが、それ以外（乗算・二乗・累乗）はむしろ簡単になる。

**最初から log 空間で設計すべきだった。** 後から移植すると全呼び出し箇所を直すことになる。

### 5.5 減衰が指数インフレの中で死ぬ

温度が 10 → 5,400 → 10^9 と伸びる世界で、減衰を「毎ターン −X」や「×0.9」にすると、序盤は即死級・終盤は誤差になり、「常時圧力」という差別化点が消える。

減衰は**温度ではなく段（対数）に対して効かせる**。ただし現状の実装（÷3 = 約0.5段）でも、相転移で1ラウンド +6.5段も伸びるので**まだ弱い**。これは未解決の課題。「到達段の20%を失う」のような定率にすべきだと考えている。

### 5.6 床がないと詰む

メトラで段が落ちると、「要 赤熱」以上のカードが一枚も着火できずハンドが完全に死ぬ。**到達最高段から1段までしか落ちない**という床を入れて解決した。

## 6. 他のゲームと混ぜるときの取り出し方

### そのまま持ち出せる骨格（テーマ非依存）

| 仕組み | 一言 | 効き目 |
|---|---|---|
| **相転移** | 閾値通過を罰ではなく恒久ブーストにする | ★★★ 指数成長が自然に出る。どんな数値ゲームにも入る |
| **加算 → 乗算 → 二乗の3層** | 効果を層に分け、層の順序が payoff を決める | ★★★ ただし単独では自明。下記と併用必須 |
| **位置に非単調な効果** | 前方参照・隣接連続・後方伝播のいずれか | ★★★ これが無いと順序ゲームは成立しない |
| **分岐過程と臨界 m=1** | 確率連鎖を分岐過程として設計し、m=1 を演出境界に | ★★★ 上限資源とセットで |
| **対数スケール = 見た目** | 段に色と名前を与え、数字を読ませない | ★★★ インフレゲーム全般に |
| **必要値 = 枠の値段** | 単調増加資源に対する必要値は、順序ではなく選択を縛る | ★★ 読み替えを間違えないこと |
| **報酬 = 倒した敵** | 障害を克服するとその障害が道具になる | ★★ カード獲得の理由づけが自動化される |
| **ノルマを数字でなく物にする** | 「10⁹点」ではなく「海を燃やす」 | ★★ スコアの意味づけが不要になる |

### 火というテーマに固有で、外すと補完が要るもの

- **「所有できない」による毎ラン初期化の正当化** — 別テーマなら、リセットが題材の本質である別の素材が要る
- **発火点の一元化** — 燃料も敵も同じ「着火点」という1つのステータスで表現できるのは火だからこそ。この統一が仕様を劇的に単純にしている（華氏451度が元ネタ）
- **正のフィードバックの物理的自然さ** — 熱→燃焼速度↑→熱↑ が説明抜きで通じる。別テーマだと相転移の理屈を別途作る必要がある
- **破滅が二種類ある**（消える／爆発する）— 伸ばす／飛ぶの両方が直感的に通じる

### 相性のいいジャンルと接続点

- **Balatro 系（役づくり）** — タグ共鳴がそのまま「役」になる。ジョーカー順序の面白さと 2.4 の知見は同根
- **Slay the Spire 系（分岐マップ）** — 森=燃料採取、廃屋=触媒、雨雲=リスク、旅商人。既に設計済み
- **インクリメンタル / 放置ゲー** — 相転移も対数表示も元々そちらの技法。1ランに圧縮しているのがこのゲームの立ち位置
- **Luck be a Landlord / Clover Pit 系（盤面配置）** — 隣接効果が既にあるので移行しやすい。ただしスロット型は「回さない選択ができる」ので、火の「焚べ続けないと死ぬ」性質とは噛み合わない（下記参照）

### 混ぜるときの注意

**「常時圧力」と「push your luck」は別物。** スロット系は回さない選択ができるが、火は焚べ続けないと死ぬ。この違いがゲームの緊張の質を決めている。前者を混ぜると後者が薄まる。

**乗算を後ろに置くコストは必ず作ること**（5.1）。これを忘れると、どんなに派手な数字を出しても意思決定が消える。

**インフレさせるなら最初から log 空間で**（5.4）。

## 8. 世界観の骨子（デフォルメの原理）

数値設計とは独立だが、章構成の背骨なので記録しておく。

**七つの太陽**（仏教・壊劫）。出典は『七日経』『起世経』『長阿含経』世記経、『倶舎論』など。太陽が一つずつ増え、二つ目で小川が涸れ、三つ目で大河が、四つ目で大湖が、五つ目で大海が涸れ、六つ目で大地と山が煙を上げ、七つ目で須弥山までが炎に包まれる。

**破壊の順序が重要**で、まず有情世間（生き物の世界）が壊れ、その後に器世間（物理的な入れ物）が壊れる。生き物は先に上位の天へ避難し、地上から誰もいなくなってから火が始まる。→ **七つの太陽が昇るとき、世界はすでに無人。プレイヤーは誰も助けず、誰にも見られず、空っぽの世界を焼く。**

**デフォルメの原理**：原典の階梯（川→大河→湖→海→大地→山→須弥山）はスケールが大きくなっているだけで、そのままでは「デカい水たまりの次にもっとデカい水たまり」になる。抽出すべきは、**燃やすたびに世界を成立させている前提が一枚ずつ剥がれていく**という構造。軸を **大きさ** から **依存** に差し替える。「それが無くなったら、上に載っているものが全部崩れるか？」を基準に並べる。

**ヘラクレイトス**をアクセントに。「万物は火の交換物であり、火は万物の交換物である。金と商品がそうであるように」——これは経済の比喩なのでそのままシステムになる。すべてのものに火の値段があるので、概念も感情も燃やせる。「メトラ」（定めの分だけ燃え、定めの分だけ消える）は毎ターンの熱損失の名前に。「エクピュローシス」（宇宙は周期的に焼かれ同じ形で再生する）が周回を正当化する。

**最後の一手**：第七章で燃やす対象を**火そのもの**にすると、二つの元ネタが一点で交わる。万物が火の交換物なら、最後に残った火を燃やすことは万物を燃やすことと同義。そして焼き尽くされた宇宙はまた同じ形で始まる——**次のランへ**。「なぜまた最初から火を起こすのか」に、ゲームが自分で答えている状態になる。
